# 可靠性优化与功能体验升级方案

检查与实施日期：2026-11-25。按日常最多约 100 个节点的使用规模验证，优先保证功能正确、保存可靠和操作流畅。

## 本次完成的优化

- 生成失败、没有可用节点或输出保存失败时，保留最后成功的工作区 YAML；独立保存配置继续保持快照语义。
- 所有订阅刷新共用最多两个任务的队列，同一订阅不会并行请求；排队状态显示为“等待刷新…”。
- 修改订阅地址、修改 User-Agent、停用或删除订阅后，不接纳旧请求的结果。地址或 UA 变化会清除旧 ETag、Last-Modified 和成功时间，但保留缓存正文。
- 相近的刷新结果在 150 毫秒内合并重建，单个订阅的缓存信息立即更新；刷新与排队期间暂停“同步到此配置”，避免同步旧内容。
- 缓存解析结果，后台抓取、工作区重建和已保存配置的节点来源列表共用缓存；正文变化后重新解析。
- 非当前工作区在独立后台线程生成；新提交使旧任务失效。后台接受输出前再次检查生成设置，并以一个数据库事务保存整批结果。
- 当前工作区保留同步生成，确保点击保存时获得当前结果。100 节点下生成耗时约 1–2 毫秒，不增加异步保存的状态复杂度。解析和生成期间不持有数据库锁。
- HTTP 成功正文在读取过程中限制为 10 MB，错误正文只读取至多 1 KB；保留响应声明的字符编码。按抓取选项复用有限数量的 HTTP 客户端。
- HTTP 发布时预计算 ETag，请求共享不可变正文；补齐 HEAD 的正文长度和弱 ETag、多个 ETag、通配符条件请求。
- 关键保存与刷新错误反馈到界面；数据库迁移采用事务；刷新日志最多保留 1,000 条。
- 将刷新、生成和后台发布从主应用文件拆出，清理编译与 Clippy 警告。
- 增加 Windows CI：格式、严格 Clippy、工作区回归、100 节点三种预设、Mihomo 语法检查和桌面 release 构建。

## 功能体验升级已完成（2026-11-25）

- 「我的配置」来源卡片提供「刷新并预览 / 预览同步」，显示新增、参数更新、上游移除和受影响引用，可统一同步多份关联配置。默认保留移除节点、本地别名、停用状态和手动字段修改；来源或配置发生变化时要求重新预览。
- 「我的配置 → 更多 → 历史版本」保留最近 20 个版本，连续一分钟内自动保存合并，重启后可恢复。恢复沿用配置 ID 和订阅地址，恢复前状态也记录在历史中；差异摘要只显示字段名，不显示密码值。
- 配置页显示未保存、保存失败或已保存状态，包括可视化表单修改；工作区失败继续提供上次成功输出。这描述 SwiftSub 的本地输出，不代表客户端已主动重新拉取。
- 「我的配置 → 更多 → 检查与处理」检查节点参数、配置引用、订阅缓存和失败刷新、本地 HTTP 正文一致性，提供编辑页跳转、刷新重试及客户端导入入口。规则源访问按需检查，最多两条并发；真实代理节点不会自动扫描。客户端导入时检测链接关联，未检测实际代理流量。
- 「设置 → 数据 → 完整备份 / 恢复」包含订阅、配置、模板、节点编辑、工作区、草稿及历史。空口令导出明文，非空口令使用 Argon2 和 ChaCha20-Poly1305 加密，最大备份文件 128 MB。恢复前预览数量，确认后恢复到独立目录，下次启动生效，原数据完整保留。

恢复后顶部持续提示重启。启用关闭到托盘时，请在托盘菜单选择「退出」再重新打开；重启前继续操作的是原数据。恢复加密备份需要原口令。

数据库迁移到版本 4，为已有配置建立历史记录。同步默认优先保留本地字段修改；上游仅改名且参数相同可识别为同一节点。升级前没有原始字段基线的节点，在首次同步时仍无法完整区分本地修改与上游参数。

### 第二批体验升级已完成

- **同步冲突逐字段选择**：同一节点字段被本地和上游分别修改时，在预览中显示冲突。默认保留本地，也可逐项接受上游，包括移除字段；嵌套设置按整个顶层字段选择。密码等内容默认隐藏。选择会保留到此次预览关闭，切换「移除上游已删除节点」不丢失选择。
- **移除节点替换向导**：打开「移除上游已删除节点」后，为每份配置的旧节点选择另一个启用节点，可选本次新增节点。同步时统一修复策略组、链式代理、监听、规则及子规则、提供者代理设置和停用状态里的引用。自动去重策略组成员；若替换产生节点或策略组循环，阻止提交，保留原配置。可清除替换选择后重新选择。
- **订阅拉取反馈**：独立配置和工作区显示「等待首次拉取 / 等待拉取当前版本 / 当前版本已拉取」及最近拉取时间。本地输出尚未完成发布时显示更新中。成功 GET 与 304 缓存确认按每份配置的内容版本记录，HEAD、错误请求及程序自身诊断请求不计入。记录每两秒保存，并在正常退出时保存，重启后保留；不保存客户端 IP 或 User-Agent。

拉取反馈只能确认订阅请求成功或缓存有效，无法确认第三方客户端已应用配置，也不能代表代理节点连通。外部浏览器或其他工具访问订阅地址同样会被计为拉取。

## 升级前的方案记录

已有功能包括节点来源同步、编辑撤销/重做、模板导入导出、导入诊断和配置追溯。后续应改善这些操作的完整流程。

### 1. 优先：刷新后展示变化，再同步到配置

当前“刷新订阅”和“同步到此配置”是分开的。建议增加“刷新并检查更新”入口，依次完成刷新、计算差异和展示影响。

差异按新增、移除、参数更新分类，默认保留本地别名、停用状态及自定义字段。对上游移除的节点明确提示受影响的策略组和链式代理，并提供替换或暂时保留选项。

用户可选择同步到当前配置或多份已关联配置；独立快照始终由用户选择后更新。同步失败不改变原配置。

验收：刷新后无需在两个页面之间切换；同步前看清变化；同步后有效配置、来源关系与本地编辑都能保留。

### 2. 优先：配置历史版本与跨重启回滚

现有撤销针对当前编辑会话。建议在成功保存、同步节点和应用模板时记录历史版本，保留最近 20 份，连续自动保存合并成一个版本。

显示时间、变更来源和摘要，例如“同步订阅：新增 3，移除 1”。提供差异查看与恢复；恢复前保存当前版本，并继续沿用原配置的订阅地址。

验收：重启后仍可恢复之前的配置；回滚不会生成新的订阅地址；失败时当前配置不被覆盖。

### 3. 优先：统一保存与生效状态

在配置页固定显示“未保存修改 / 已保存 / 使用上次成功输出 / 保存失败”，同时显示上次成功更新时间。工作区与独立配置使用一致的状态文案。

发生错误时提供直接入口，例如跳转到有问题的规则或代理组，而不是要求用户从诊断报告自行查找。刷新失败可直接重试，并提示继续使用缓存。

验收：用户始终知道正在编辑的内容是否已经保存、客户端正在获取哪一份配置。

### 4. 后续：把诊断升级为可操作的检查列表

在现有导入诊断与配置追溯基础上，增加本地订阅可访问性、配置引用、客户端导入和规则源可用性检查。区分阻止使用的问题与建议，不以全部检查通过作为普通操作的前提。

每项提供具体处理入口；导出报告默认隐藏凭据。真实节点连通性检查作为按需操作，不自动扫描全部节点。

### 5. 后续：完整备份与恢复

提供本地备份包，包含订阅源、配置正文、模板、节点编辑及关联信息。恢复前展示将新增或覆盖的内容，默认导入副本，避免无提示覆盖现有数据。

含凭据的备份由用户明确选择导出，并可选口令加密。验收重点是换电脑后恢复完整工作状态，而不仅是导出 YAML。

推荐顺序：刷新差异与同步 → 历史回滚 → 保存与生效状态 → 可操作诊断 → 完整备份恢复。
