# 围绕 Clash YAML 简化流程

日期：2026-11-25。本轮修改已实施，检查与构建记录见文末。

本文保留 11 月 25 日的实施记录。11 月 26 日按最新要求，生成页的完成动作已改为「保存到我的配置 / 导入 Clash Verge」，移除生成页导出，复制收进「更多」，详见 [保存与导入优化说明](GENERATOR_SAVE_IMPORT_REFINEMENT.md)。

## 产品定位

核心任务是帮助用户写出可直接使用的 Clash / Mihomo YAML。用户日常只需添加节点、编辑策略组与规则，然后复制或导出文件。

原流程默认进入订阅管理，主导航并列放置订阅源、配置生成、我的配置、模板、设置；复制和导出藏在次级菜单里，保存配置又会进入另一套编辑页。本地订阅地址和发布状态占据主界面，容易让用户误以为必须先理解服务、工作区、配置库、模板才能得到 YAML。

## 本轮实现

| 原来的负担 | 简化后的操作 |
| --- | --- |
| 默认进入订阅源管理，再切到生成页 | 默认进入配置编辑，空节点区直接提供添加入口 |
| 五个同等重要的页面 | 主导航保留配置编辑、我的配置、设置；来源和模板管理作为编辑页的辅助入口 |
| 添加订阅必须离开编辑页 | 节点区直接打开添加订阅 / 节点链接弹窗；剪贴板导入和从 YAML 提取节点仍可使用 |
| 复制与导出藏在菜单 | 编辑页顶部直接提供「复制 YAML」「导出 YAML」，无需先保存到配置库 |
| 主界面展示本地 HTTP 服务与发布状态 | 主界面只显示当前 YAML 状态；服务状态、地址与详细输出状态留在本地订阅设置 |
| 保存配置被当作核心完成动作 | 存档放在「更多 → 保存到我的配置」；编辑已有存档时显示「更新原配置」并提供另存入口 |
| 普通配置也显示重复另存操作 | 新配置不显示重复的另存菜单；预览不再重复放复制按钮 |
| 新用户默认启用较多服务模块 | 新用户默认使用精简模板；已有模板与模块设置继续读取，明确保存的配置不重置 |
| 设置初始进入本地服务 | 默认进入规则与生成；基础 DNS 和测速已有默认值，可直接使用 |
| 多工作区与高级 JSON 默认占据主要位置 | 多工作区从数据设置打开；高级 JSON 默认收起，基础与 DNS 仍直接可见 |

来源管理页和模板管理页均保留直接返回配置编辑的入口。组参数、成员、添加规则和规则正文编辑继续留在当前组旁，节点编辑与二维码继续直接可用。

## 日常流程

1. 打开软件，在节点区添加订阅或节点链接。
2. 使用精简模板；需要时在当前页调整策略组、成员和分流规则。
3. 点击复制 YAML 或导出 YAML，放入 Clash / Mihomo 使用。

DNS、测速、端口等已有默认值，不是导出前必须逐项配置的步骤。模板管理、配置存档、本地自动刷新订阅、历史记录、链式代理、多工作区与高级参数保留为有具体需要时使用的辅助功能。

已有完整 YAML 的导入与直接编辑继续通过「我的配置 → 导入 YAML」完成，保留原文件的节点、规则和扩展字段；编辑页添加弹窗中的 YAML 导入明确用于提取节点。这两种导入用途没有合并成一个会悄悄覆盖内容的操作。

## 输出一致性

复制与导出先校验并应用当前组参数和规则，再从当前节点及配置生成 YAML。无效规则、没有启用节点或未保存的规则正文会给出具体原因，不会把旧缓存文件误当成当前编辑结果输出。

输出文件不依赖先创建存档或配置本地订阅服务。工作区仍保留自动保存与错误草稿，配置库存档保持独立，已有手工 YAML 不会被工作区自动生成覆盖。

## 后续约束

- 不为每个后台能力增加一级页面。
- 不增加必须依次点击完成的步骤向导；常用编辑仍在同一页。
- 少量固定模式直接显示；来源、模板、组等实际数据可使用选择器。
- 常用节点与规则功能留在对象旁；低频管理入口可以作为辅助操作。
- 基础默认值直接可用，高级字段按需打开，不要求用户逐项填写。
- 后台仍保留工作区与存档的数据边界；本轮没有迁移数据库或强行把它们合并。后续如统一完整 YAML 编辑与可视化工作区，必须先保证未知字段、草稿及订阅刷新不会丢失。
