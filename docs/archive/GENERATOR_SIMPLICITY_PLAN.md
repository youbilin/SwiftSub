# 配置生成简约与就地操作方案

状态：已实施并完成本轮验收（2026-11-25）。本文覆盖此前整改计划中将组参数迁往总设置、将组规则放入独立管理窗口的安排。

## 1. 用户意图与整改方向

生成页要方便完成当前配置的操作：选节点、调整组、选成员、添加规则、查看和编辑规则、保存配置。总设置负责日常无需反复填写的默认值：DNS、测速、分流测试、端口、局域网与规则下载来源。精简的是默认呈现的信息量，常用功能应留在操作对象旁。

此前实现存在三处方向错误：组设置跳转总设置，打断编辑；组规则打开另一套管理窗口，失去组上下文；规则库偏重来源和勾选，添加、查看、编辑的流程没有围绕当前组组织。现有解析、校验和持久化能力保留，重新整理入口和交互。

## 2. SubBoost 的具体参考

参考版本：`2832bcff66765d1f3843452b00b4a8bc4745b03d`，本轮对照仓库源码，不宣称完成其线上交互实测。

| 参考文件 | 本次采用的交互原则 |
| --- | --- |
| `proxy-groups-module-card.tsx` | 组行呈现摘要，组旁保留设置入口，展开内容仍属于该组 |
| `proxy-group-advanced-panel.tsx` | 已选成员和分流规则在同一组编辑区呈现 |
| `proxy-groups-rules-library.tsx` | 搜索、选择规则，再添加到指定组；添加时明确目标 |
| `proxy-groups-added-rule-sets.tsx` | 已添加规则集可编辑、删除，编辑状态留在当前列表 |

按上述操作关系独立实现。DNS 与测速入口遵循用户要求集中到总设置，不照搬参考项目的全部分区。

## 3. 功能放置表

| 功能 | 位置与操作 |
| --- | --- |
| 节点启停、排序、搜索、编辑、二维码 | 保留生成页现有节点区，编辑和二维码直接可用 |
| 模板选择、保存当前配置、预览 | 保留生成页顶部 |
| 新建组、组启停、组类型 | 分流区与对应组行 |
| 组名、说明、负载均衡策略等组自身参数 | 对应组旁的设置入口，就地展开小面板 |
| 成员选择、排序、引用其他组 | 当前组内部 |
| 已绑定规则、添加规则、查看内容、编辑内容 | 当前组内部；不切页面，不打开另一套规则管理窗口 |
| 基础 DNS、测速地址/周期/容差、分流测试默认项 | 顶部总设置，保存后继承 |
| DNS 覆写 | 生成页保留一个开关，使用总设置中的 DNS |
| 默认模板、规则来源、下载镜像 | 总设置；当前配置绑定哪些规则仍在生成页操作 |
| 自定义规则 | 当前组规则区按需添加，目标默认为当前组 |
| 全局规则顺序 | 分流区的次级入口，就地展开排序；不在默认界面铺开 |
| 筛选组、链式代理 | 保留生成页工具入口和就地编辑能力，能直接作为成员或规则目标使用 |
| 删除组 | 自定义组行旁的垃圾桶图标直接删除，引用自动转到「节点选择」；不展开删除表单，不提供复制组入口 |
| 导出、模板保存等次级操作 | 对应区域的菜单；常用成员和规则操作不藏入菜单 |

现有单组测速覆写继续保留和读取，总设置高级项可编辑。生成页不默认展示测速表单。

## 4. 默认生成页与组展开状态

维持现有节点区、分流区、按需预览的关系，不再次交换布局。顶部只保留模板选择、预览、保存配置及必要的次级菜单。分流区标题旁保留 DNS 覆写，新建组放在组列表顶部。

组收起时呈现一行：名称、类型、成员数、规则集/自定义规则摘要、启停与就地设置入口。规则集数量和真实规则条数分开；只有实际读取内容后才显示内容条数。

组展开后仅显示当前组的编辑内容：

```text
AI 服务      手动选择                   启用  设置
成员：香港节点、自动选择……               编辑成员
规则：
  OpenAI       MetaCubeX                 查看 / 编辑
  Gemini       MetaCubeX                 查看 / 编辑
                                       ＋ 添加规则
```

成员和规则都在原组下操作。默认只呈现已选成员摘要和已绑定规则，候选节点列表、完整规则库、参数表单分别按需打开。较长列表使用限定高度滚动，并保留查看全部入口；用户展开时不主动换页、清空搜索或重置滚动。

组设置打开当前组的小面板：名称、说明及适用的组参数。手动选择组不显示负载均衡选项；负载均衡组可以就地改策略。需要调整名称或类型时无需先到总设置重新选择组。

## 5. 添加规则：选进当前组

1. 点击当前组的「添加规则」，直接在该组下面展开选择区。
2. 选择区默认提供一个搜索框和结果列表；来源筛选作为一个下拉，不列出全部来源工具栏。
3. 搜索 `OpenAI`、`Netflix` 等名称，勾选所需规则，可多选。未搜索时显示少量常用候选，不一次铺开整个目录。
4. 点击「添加到 AI 服务」，已选规则进入该组的规则列表，候选区收起。操作不需要再次选择目标组。
5. 已在当前组的规则标明「已添加」并避免重复。已在其他组的规则标明归属，明确选择移入当前组后才更改原归属，不能因勾选而悄悄改动别的组。

自定义链接与手写规则作为同一添加区的次级选项，选择后才显示输入框。手写规则默认绑定当前组，保存时检查格式。添加内置来源中的规则不应顺带启用原来源服务组或加入未选的兄弟规则。

## 6. 查看与编辑规则

点击组内规则集的「查看 / 编辑」，在同一组下面打开内容编辑区。顶部显示名称、来源、内容类型和实际条数；正文可搜索、查看并修改具体域名、IP 或 classical 规则，不能只提供名称、链接和勾选。

正文只读查看和进入编辑使用同一个区域。编辑时提供保存、取消与恢复来源；错误反馈在输入附近。内容保存到当前配置的规则覆写，原始来源链接保留。恢复来源撤销覆写并重新使用上游规则。

规则集链接、名称、类型和 `no-resolve` 等元数据从该规则行的次级编辑入口调整，不在每行放一整排输入框。启停、移除和改目标同样在该组内完成。规则移走后两组列表及计数立即一致；来源组启停不应隐式关闭已经移走的规则。

YAML 和 TXT 兼容来源注释、逐行规则与 YAML payload；MRS 已实现原生解码，支持 domain 与 ipcidr，并在解码失败时尝试同路径文本版本。读取失败保留草稿，不要求用户先离开当前组。

## 7. 默认值与保存行为

总设置保存默认参数，各生成工作区继承；DNS 开关决定是否使用用户保存的 DNS。组自身的类型、成员、规则及已存在的独立覆写属于当前配置。更换模板不改写全局默认。

有效编辑自动校验并更新工作区输出，错误内容就地保留且不替换上次有效结果。内容编辑中的未保存文本在收起、切换编辑对象和退出时保留为草稿；重新打开可以继续。

「保存配置 / 更新原配置」继续明确写入配置库。工作区自动生成不自动覆盖已保存或手工修改的 YAML。生成、预览、导出、保存和本地订阅输出从同一有效配置得到。

规则仅在用户查看时读取，异步加载并缓存，不预先下载所有规则集。节点数量仍以 100 个验证；长正文只影响当前内容区，不阻塞成员选择与其他组操作。

## 8. 实施顺序

1. **修正入口**：取消组参数跳转和独立规则管理窗口；恢复组内成员、规则、就地参数操作。
2. **完成添加流程**：组内搜索、多选、添加、归属提示、自定义链接与手写规则。
3. **完成内容编辑**：组内查看、搜索、编辑、取消、恢复来源，补齐规则格式与 MRS 支持。
4. **统一继承与状态**：全局默认、当前配置、规则覆写、草稿及已保存配置边界保持一致。
5. **功能验收并构建**：只进行必要的实际操作、100 节点保存与重启检查、Mihomo 校验，不追加大批布局截图或压力测试。

## 9. 交付验收

- 新建组、改类型、改名、选成员、调成员顺序、添加规则、查看与编辑规则，全程不离开配置生成页。

- 默认生成页没有测速地址、测速周期、基础 DNS 表单或整块规则库。
- 打开组不会同时展开候选节点、所有来源、所有参数和规则正文。
- 添加规则不重复选目标，不意外启用其他组，不出现重复绑定。
- 规则内容可以实际读取并编辑；保存、恢复来源、规则移组及组启停后，列表和输出一致。
- 节点编辑与二维码直接可用；筛选组、链式代理、自定义规则、模板与导出功能均保留。
- 100 节点完成「选节点 → 改组 → 添加/编辑规则 → 保存 → 重启 → 核对 YAML 和 HTTP」；代表性配置通过 Mihomo。

## 10. 实施结果与验证

- 组设置、成员、规则添加、元数据和正文编辑均留在当前组内。筛选组、链式代理也可以就地绑定规则；全局规则顺序从顶部「更多」在原分流区展开。

## 11. 策略组编辑与错误定位修复（2026-11-25）

- 根因：草稿中的 `aaa` 被规则列表的解析过滤隐藏，但保存组参数及打开内置组时仍会解析全部规则，导致用户无法找到错误并被阻挡编辑。
- 组参数校验与全局规则校验分开；改组名时更新有效引用，保留无效行和注释以便修复。有效组参数可先保留到草稿，未完成规则不会发布为有效配置。
- 分流区顶部显示错误原文、具体行号及格式示例。启动时存在无效规则会打开实际草稿，收起后可通过「定位并修改」重新打开；支持应用修正及恢复上次有效规则。
- 组名、测速地址、间隔和容差校验错误明确说明组名及字段；内置组打开失败也显示具体原因。
- 自定义策略组、筛选组与链式代理使用直接垃圾桶入口，删除引用转到「节点选择」；清除旧删除展开表单和状态。生成页与我的配置均移除复制策略组入口；必需内置组保留，内置覆写可在组设置内恢复默认。
- 本次修复后的完整工作区测试共 121 项通过，严格 Clippy 与格式化通过。补充回归覆盖无效规则保留、具体行号及内置组不受无关无效配置阻挡；随后清理删除表单，再运行 App 回归与严格 Clippy。Release 产物为 `target/release/swiftsub.exe`。
- 隔离的 100 节点草稿复现了 `aaa`，确认启动时错误原文和修复输入可见；按用户要求停止截图和桌面操作，剩余验证采用源码复查、回归测试与构建，不宣称完成所有桌面交互实测。用户实际数据库只读，未自动清除其中的无效草稿。
