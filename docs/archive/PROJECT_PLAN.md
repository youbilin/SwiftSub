# SwiftSub 项目计划

> 版本：v0.1 · 日期：2026-11-12
> 定位：Clash / Mihomo 订阅转换本地版
> 技术路线：Rust + GPUI
> 参考产品：SubBoost（仅参考公开的产品行为，不复用其源码与资源）

---

## 1. 项目概述

### 1.1 一句话定位

SwiftSub 是一个运行在本机的 Clash/Mihomo 订阅工作台：导入机场订阅、节点链接或 YAML，可视化完成聚合、去重、改名、筛选、链式代理与分流配置，生成可直接使用的 Mihomo 配置，并通过本地订阅地址自动刷新给 Clash 客户端。

### 1.2 要解决的问题

- 多个机场、自建节点的订阅分散，节点重复、命名混乱，手动合并成本高。
- 在线转换服务需要把含密钥的订阅链接上传到第三方，存在隐私顾虑；SubBoost 功能完整但依赖 Docker/Web 部署。
- 图形化工具大多只是“格式转换”，缺少链式代理、精细分流、防 DNS 泄漏等进阶能力。
- 生成的配置难以持续维护：机场节点变化后需要重新转换，缺少自动刷新与本地分发能力。

### 1.3 产品原则

1. **本地优先**：订阅、节点、配置只保存在本机，无账号、无云端、无遥测。
2. **轻量**：单个可执行文件，无 Node/Docker/数据库服务依赖；目标安装包小于 30 MB。
3. **可视化且可验证**：所有生成结果可实时预览、可校验、可回溯到具体节点与规则。
4. **安全默认值**：默认防 DNS 泄漏、本地服务仅监听回环地址、订阅密钥脱敏显示。
5. **干净实现**：只借鉴 SubBoost 的产品行为与交互，不复制其 AGPL 代码、样式与规则元数据。

### 1.4 目标用户

- 使用多个机场、需要统一聚合与去重的 Clash/Mihomo 用户。
- 需要“中转 + 落地”链式代理，或按服务精细分流的高级用户。
- 希望把一份订阅分发给手机、路由器等设备的用户。
- 不愿把订阅链接上传到在线转换网站、重视隐私的用户。

### 1.5 成功标准

- 新用户 5 分钟内完成：添加订阅 → 选择模板 → 复制本地订阅地址 → 导入 Clash。
- 生成配置通过 `mihomo -t` 校验；节点刷新后旧配置不失效（保留最后一次成功结果）。
- 500 节点、100 代理组、2000 条规则的本机生成耗时低于 100 ms。
- 冷启动低于 1 s，空闲内存低于 150 MB，发布包小于 30 MB。

## 2. 范围

### 2.1 目标（v1.0）

- 订阅源管理：URL、Clash/Mihomo YAML、Base64 节点列表、纯节点链接、本地文件。
- 多订阅聚合、去重、批量改名、启用/禁用、排序、监听端口。
- 筛选代理组、链式代理（1–3 跳）、中转组与落地组可视化。
- 预设模板（精简/标准/完整）与数据驱动的代理组/规则模块。
- 自定义规则、规则排序、规则集目录选择、规则引用校验。
- 默认防 DNS 泄漏配置 + 常用项可视化 + 高级 YAML 编辑。
- 实时 YAML 预览、统计、复制、导出、二维码。
- 本地 HTTP 订阅地址（Token 保护）+ 定时刷新 + 流量/到期信息。
- 本地 SQLite 持久化、配置自动保存、日志与错误提示。

### 2.2 非目标

- 不提供任何代理服务，不销售节点。
- 不内置 Clash/Mihomo 内核，不替代 Clash 客户端。
- 不做多用户、账号体系、云同步、在线托管。
- 不做订阅分享社区、节点测速排行、广告。
- v1.0 不做系统托盘、开机自启、自动更新（列入 v1.1+）。

## 3. 技术方案

### 3.1 选型

| 领域 | 选择 | 理由 |
| --- | --- | --- |
| 语言 | Rust stable（>= 1.90，edition 2024） | 性能、单文件分发、内存安全 |
| UI | GPUI + GPUI Kit 0.9.x（含 gpui-component） | GPU 渲染、原生桌面、组件齐全；精确锁定版本 |
| 状态与事件 | GPUI Entity + mpsc 通道 | UI 线程不阻塞，后台任务回报事件 |
| 配置解析/生成 | `serde`、`serde_yaml_ng`、`indexmap` | 保留字段顺序，兼容 Mihomo YAML |
| 订阅抓取 | `reqwest` blocking + rustls + socks | 支持 HTTPS/SOCKS 代理、重定向、超时；隔离在 Fetcher trait 后 |
| 本地订阅服务 | `tiny_http` + 独立线程 | 仅 3 个只读端点，无需引入 tokio/axum |
| 持久化 | `rusqlite`（bundled SQLite）+ WAL | 无需外部服务，事务可靠，便于后续多 Profile |
| 调度 | 标准线程 + 持久化下次刷新时间 | 轻量，避免额外运行时 |
| 二维码 | `qrcode` | 生成 PNG/SVG，供手机扫码导入 |
| 文件选择 | `rfd` | Windows 原生文件对话框 |
| 日志 | `tracing` + 文件滚动 | 便于排查订阅抓取与生成问题 |
| 测试 | `insta` 快照、`tempfile`、`mockito` | 协议样本与 golden YAML 回归 |
| 打包 | `cargo build --release` + `cargo-packager` | 便携版 zip + NSIS/MSI 安装包 |

### 3.2 关键取舍

**GPUI 生态处于 pre-1.0。** 当前 gpui-component / GPUI Kit 基于 `gpui-pre` 快照（0.3.x），API 可能破坏性变更。策略：

- 在 M0 锁定精确版本（示例：`gpui-kit = "=0.9.1"`、`gpui-pre = "=0.3.12"`），提交 `Cargo.lock`。
- UI 层只做展示与交互，所有业务逻辑放在 `swiftsub-core`，降低框架升级成本。
- 只在里程碑节点评估升级，不在功能开发中途升级。
- 若 GPUI Kit 体积或稳定性不达标，回退到官方 `gpui` + 少量自绘控件，架构不变。

**不引入 tokio/axum 作为主运行时。** 订阅抓取、存储、HTTP 服务均为低频任务，使用独立线程即可；GPUI 本身使用 smol 生态，双运行时收益低。若后续本地服务扩展到较多端点，再评估迁移 axum。

**SQLite 而非 JSON 文件。** 订阅、节点覆盖、模板、刷新日志有关联关系，需要事务与增量更新；SQLite 仍是单文件本地存储，不引入服务进程。设置项同时支持 JSON 导入/导出以便迁移。

**YAML 输出策略。** 使用 `indexmap` 保持字段顺序；高级 YAML 解析合并后统一序列化，注释不保留（UI 中明确提示）。生成后做引用校验，可选调用外部 `mihomo -t` 二次验证。

### 3.3 开发环境

- Windows 11 x64（首要目标），Rust stable，VS 2022 Build Tools + Windows SDK。
- Git、Node.js 仅用于辅助脚本（生成图标、规则目录），不进入运行时。
- 跨平台：代码保持 macOS/Linux 可编译，CI 做构建检查；v1.0 只对 Windows 做完整 QA。

## 4. 架构设计

### 4.1 分层

```
┌─────────────────────────────────────────────────────────────┐
│ swiftsub-app（GPUI）                                        │
│  页面 / 组件 / 状态 / 命令分发 / 预览渲染                    │
└───────────────┬───────────────────────────▲─────────────────┘
                │ commands                  │ events
┌───────────────▼───────────────────────────┴─────────────────┐
│ AppService（应用编排层）                                     │
│  导入、刷新、生成、保存、服务开关、调度触发                   │
└───────┬──────────────┬──────────────┬──────────────┬────────┘
        │              │              │              │
┌───────▼──────┐ ┌─────▼──────┐ ┌─────▼──────┐ ┌────▼────────┐
│ swiftsub-core│ │swiftsub-   │ │swiftsub-   │ │swiftsub-    │
│ 解析/规范化  │ │fetch       │ │store       │ │server       │
│ 分组/规则/DNS│ │订阅抓取    │ │SQLite      │ │本地 HTTP    │
│ YAML 生成    │ │userinfo    │ │迁移/缓存   │ │Token/QR     │
└──────────────┘ └────────────┘ └────────────┘ └─────────────┘
```

依赖方向：`app` 依赖所有下层；`server` 读取 store 中的“最后一次成功配置”；`core` 不依赖 IO、数据库、UI，可独立测试与复用（未来 CLI）。

### 4.2 工作区结构

```
SwiftSub/
├─ Cargo.toml                  # workspace，锁定工具链
├─ rust-toolchain.toml
├─ crates/
│  ├─ swiftsub-core/           # 纯逻辑库
│  │  ├─ model/                # Proxy、Node、Subscription、Template、Profile
│  │  ├─ parser/               # clash-yaml、base64、节点链接、协议解析
│  │  ├─ normalize/            # 字段规范化、去重、改名、区域识别
│  │  ├─ generator/            # proxies / groups / rules / dns / base / yaml
│  │  ├─ rules/                # 模块目录、规则集目录、排序、引用校验
│  │  └─ template/             # 精简 / 标准 / 完整 + 自定义模板
│  ├─ swiftsub-fetch/          # 抓取、UA、代理、重试、userinfo 解析
│  ├─ swiftsub-store/          # SQLite、迁移、设置、缓存
│  ├─ swiftsub-server/         # 本地订阅 HTTP、Token、响应头
│  └─ swiftsub-app/            # GPUI 桌面应用（bin: swiftsub）
├─ assets/                     # 图标、字体、规则目录、示例配置
├─ docs/                       # 产品与架构文档
├─ tests/fixtures/             # 协议样本、订阅样本、golden YAML
└─ scripts/                    # 规则目录生成、mihomo 校验、打包
```

### 4.3 线程与状态模型

- **UI 线程**：只做渲染与交互，不执行网络、磁盘、YAML 生成。
- **生成任务**：GPUI 后台执行器；配置变更后 200 ms 防抖，带递增 epoch，过期任务丢弃。
- **网络任务**：2–4 个 fetch 工作线程，结果通过 mpsc 回到 AppService。
- **存储**：StoreActor 单线程持有 SQLite 连接，命令串行化，避免锁竞争。
- **本地服务**：独立线程 + `Arc<RwLock<CachedProfile>>`，请求只读缓存，不查库。
- **调度器**：独立线程每 30 s 检查到期订阅；刷新成功原子替换缓存。

`CachedProfile` 包含：YAML 文本、生成时间、节点/组/规则统计、ETag、来源版本号。生成失败时保留最后一次成功结果，并在 UI 提示。

### 4.4 转换流水线

```
订阅源 / 文件 / 链接
        │
        ▼
[1] 获取与识别：URL / YAML / Base64 / 多行链接 / JSON
        │
        ▼
[2] 解析：协议链接 → 统一 Proxy 模型；YAML 字段 → 规范化模型
        │
        ▼
[3] 校验与告警：必填字段、未知协议、重复节点（逐条收集，不中断全局）
        │
        ▼
[4] 去重与合并：按身份指纹合并多来源节点，保留来源标签
        │
        ▼
[5] 覆盖层：启用/禁用、别名、排序、监听端口（按指纹稳定匹配）
        │
        ▼
[6] 筛选与链式：筛选组、落地组、dialer-proxy 生成
        │
        ▼
[7] 代理组：按模板与模块开关生成组，剔除空地区组
        │
        ▼
[8] 规则与 DNS：规则集、自定义规则、排序、引用校验、DNS/基础配置
        │
        ▼
[9] 序列化与校验：YAML 输出、内部引用检查、可选 mihomo -t
        │
        ▼
[10] 缓存与分发：SQLite/原子文件、预览、导出、本地订阅地址
```

节点身份指纹：`hash(type, server, port, uuid/password/psk, network, sni)`，不使用名称；机场改名后覆盖设置仍能匹配，指纹变化时回退到“来源 + 原名”匹配并提示。

## 5. 数据设计

### 5.1 SQLite 表

| 表 | 关键字段 | 用途 |
| --- | --- | --- |
| `subscriptions` | id, name, kind, url, user_agent, enabled, refresh_minutes, last_ok_at, last_error, etag, payload, node_count, traffic_* , expire_at, sort_order | 订阅源与最后一次抓取结果 |
| `node_overrides` | sub_id, node_key, alias, enabled, listen_port, sort_order, extras | 用户对节点的修改 |
| `templates` | id, name, builtin, config_json, created_at, updated_at | 内置与自定义模板 |
| `profiles` | id, name, template_id, token, options_json, last_yaml, generated_at | 生成结果与订阅令牌（v1.0 单 Profile，表结构支持多 Profile） |
| `settings` | key, value | 全局设置 |
| `refresh_logs` | id, sub_id, at, ok, message | 刷新历史与排错 |

迁移使用 `PRAGMA user_version` 递增；开启 WAL；写操作事务化；配置文件使用“临时文件 + rename”原子替换。

### 5.2 数据目录

- 默认：`%APPDATA%\SwiftSub\`（`swiftsub.db`、`logs/`、`cache/`）。
- 便携模式：可执行文件同目录存在 `portable.flag` 时，使用 `.\data\`。
- 设置页展示数据目录并支持“打开目录 / 导出备份”。

### 5.3 敏感数据处理

- 订阅 URL 可能包含令牌：列表中脱敏显示，日志不打印完整 URL 与响应头。
- 默认只监听 `127.0.0.1`；开启局域网访问需显式确认并展示风险提示。
- 本地订阅地址使用 128 位随机 Token；支持一键轮换。
- v1.1 评估使用 Windows DPAPI 加密存储订阅 URL。

## 6. 关键功能设计

### 6.1 订阅导入与抓取

- 支持：订阅 URL、上传 YAML、粘贴 YAML、粘贴多行节点链接/Base64、本地文件拖放。
- 抓取：自定义 UA、超时、重定向、HTTP/SOCKS5 代理（直连/系统/自定义）、失败重试、ETag/Last-Modified 条件请求。
- 识别 `subscription-userinfo`（上传/下载/总量/到期），展示剩余流量与到期日；多订阅聚合统计并回传给本地客户端。
- 抓取失败保留上次成功数据，记录错误与时间；提供“仅预览缓存”。
- 同一 URL 默认按指纹去重，避免重复添加。

### 6.2 节点管理

- 列表：协议、原名、别名、来源、地区、启用状态、监听端口、排序。
- 搜索与筛选：全部 / 已启用 / 已排除 / 有告警 / 按来源 / 按地区。
- 批量操作：启用、禁用、删除、前后缀、正则替换、按模板改名、设置区域。
- 区域识别：国旗、ISO 代码、常见中英文城市/机场关键词，支持自定义映射。
- 监听端口：为节点生成 Mihomo `listeners`（mixed，默认 127.0.0.1），端口唯一性校验与占用提示。
- 告警逐条可查看：未知协议、缺失字段、重复节点、端口冲突。

### 6.3 筛选代理组

- 规则：来源、地区、关键词包含、关键词排除、协议。
- 实时显示命中数量与节点预览；空组不写入配置并在 UI 提示。
- 可作为普通代理组使用，也可作为链式代理的落地组。
- v1.1 支持节点延迟条件（依赖 Clash API）。

### 6.4 链式代理

- 结构：中转组（入口候选）→ 落地组（出口候选），支持 1–3 跳。
- 生成方式：为落地节点生成副本，设置 `dialer-proxy` 指向中转组；多跳时中间节点同样带 `dialer-proxy`。
- 命名：确定性生成（如“中转/落地”前缀 + 原名 + 序号），避免与源节点冲突。
- 中转组类型支持 select / url-test / fallback；健康检查 URL 与间隔可配置。
- 可视化展示“我的流量 → 中转节点 → 落地节点 → 目标服务”，与生成结果一一对应。
- 链式节点可单独设置监听端口，便于外部程序固定出口。

### 6.5 代理组与规则

- 数据驱动模块：每个模块 = 代理组定义 + 关联规则集 + 默认目标组；新增服务只需添加目录项。
- v1.0 模块目标 40+：基础组（选择/自动/故障转移）、地区组（港台日韩新美英德法等）、服务组（AI、Google、YouTube、流媒体、社交、Telegram、GitHub、Microsoft、Apple、游戏、支付、广告拦截、私有网络、国内直连、漏网之鱼）。
- 模板：精简（基础组 + 国内外分流）、标准（常用服务组）、完整（全部模块 + 扩展规则集）。
- 规则集目录：内置常用条目；完整 2000+ 目录从公开上游按需下载并缓存，支持 GitHub/jsDelivr 镜像切换。
- 规则类型：DOMAIN、DOMAIN-SUFFIX、DOMAIN-KEYWORD、GEOIP、GEOSITE、IP-CIDR、IP-CIDR6、SRC-IP-CIDR、DST-PORT、SRC-PORT、PROCESS-NAME、PROCESS-PATH、RULE-SET、MATCH。
- 自定义规则：表单编辑 + 原始文本批量导入；目标组下拉选择；`no-resolve` 开关。
- 排序：拖拽调整；内置顺序建议（广告拦截 → 私有网络 → 国内直连 → 服务分流 → GEOIP → MATCH）。
- 校验：引用了不存在或被禁用的组时，UI 标红并提供“修复为节点选择/直连”。

### 6.6 DNS 与基础配置

- 默认防泄漏方案：fake-ip、fake-ip-filter（局域网、NTP、STUN 等）、国内 DoH/DoT 与国外 DoH 分流、`proxy-server-nameserver`、`nameserver-policy`，默认开启 `respect-rules`（以 M0 对 Mihomo 实测为准）。
- 可视化常用项：IPv6、fake-ip 范围、国内/国外 DNS、fallback、缓存。
- 高级模式：直接编辑 DNS YAML，实时解析校验，错误定位到行。
- 基础配置：mixed-port、allow-lan、mode、log-level、unified-delay、tcp-concurrent、sniffer、geodata、external-controller（可选）。

### 6.7 预览与校验

- 右侧实时预览：只读代码视图（行号 + 语法高亮），YAML / 可视化双视图。
- 统计：节点数、代理组数、规则数、规则集数、告警数。
- 校验报告：YAML 语法、组引用、规则目标、端口冲突、空组、重复节点。
- 可选外部校验：检测到 `mihomo` 可执行文件时，执行 `mihomo -t -f` 并展示结果；不随应用分发内核。
- 操作：复制、导出 `.yaml`、保存为 Profile、二维码。

### 6.8 本地订阅服务

- 默认监听 `127.0.0.1:7899`，可修改端口；默认禁止局域网访问。
- 地址：`http://127.0.0.1:7899/sub/<token>/clash.yaml`；Token 可轮换。
- 响应头：
  - `Content-Type: text/yaml; charset=utf-8`
  - `Profile-Update-Interval: <小时>`
  - `Subscription-Userinfo: upload=...; download=...; total=...; expire=...`
  - `ETag` / `Last-Modified`，支持 304，减少客户端重复下载。
- 只处理 GET/HEAD；只读缓存；无目录遍历；限制并发；CORS 关闭。
- 支持复制地址与二维码；开启局域网时提示“同网段设备可访问，请勿在不可信网络使用”。

### 6.9 自动刷新

- 每个订阅独立刷新间隔，默认 24 小时，最小 15 分钟；加入 ±5% 抖动。
- 失败退避：1 小时 → 6 小时 → 24 小时；连续失败在订阅卡片显示。
- 刷新成功后：更新订阅缓存 → 标记配置为脏 → 后台重新生成 → 原子替换本地服务缓存。
- 应用关闭即停止刷新（v1.0 限制，明确写入 UI）；v1.1 通过托盘常驻解决。
- 提供“全部刷新”和“打开应用时检查更新”。

### 6.10 模板

- 内置三套模板，保存为结构化 JSON；模板包含组开关、规则集开关、规则顺序、DNS、基础配置、链式定义。
- 自定义模板：基于当前配置另存为、重命名、删除、导入/导出 JSON。
- v1.1 支持导入 SubBoost 风格的模板配置（仅结构兼容，不复用代码）。

### 6.11 设置

- 通用：主题（深色默认/浅色/跟随系统）、语言（中文，预留英文）、启动页。
- 网络：拉取方式（直连/系统代理/自定义 HTTP/SOCKS5）、超时、默认 UA、并发数。
- 服务：端口、局域网开关、Token 轮换、复制地址、二维码。
- 规则：规则集基础地址、镜像切换、目录更新。
- 数据：数据目录、导出备份、清理缓存、查看日志。
- 关于：版本、开源许可、手动检查更新链接。

- 去重、区域识别、启用/禁用、标准模板、31 个分流模块、规则集、防泄漏 DNS、YAML 生成。
- 筛选代理组：按地区与包含/排除关键词筛选节点，持久化并实时生成。
