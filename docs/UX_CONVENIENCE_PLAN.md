# 操作便利性与编辑体验优化计划

日期：2026-11-26。状态：P0 / P1 的主要代码改动已实施，发布与验证记录见第 11 节；P2 已完成字段保留边界评估，尚未合并两套编辑器。本轮仅检查源码、运行代码回归和构建，不截图、不操作用户窗口。

## 1. 目标与设计约束

软件的主要任务是帮助用户整理节点、写好分流，再保存到我的配置或导入 Clash Verge。优化必须同时减少操作步骤、明确当前编辑对象、保留完整编辑能力。

- 保持现有节点、策略组和预览的区域位置；在区域内部整理操作和信息层级。
- 节点列表直接可见，成员、添加规则、规则正文编辑继续在当前组内使用。
- DNS、测速、端口等沿用总设置默认值。生成页只保留 DNS 覆写开关，不增加参数表单或测试入口。
- 生成页的主要完成动作仍是保存、导入 Clash Verge，不恢复导出 YAML。
- 不新增一级页面，不恢复复制策略组，不把常用功能移入更多菜单。
- 将常用操作做短，将低频参数按需显示；不靠隐藏节点、截断规则目录或删除功能来实现简约。

## 2. 实施前确认的问题

以下为实施前的源码审核基线，保留用于说明整改原因；操作次数由按钮和菜单路径推导，不是桌面实测。整改后的路径与测量结果见第 8、11 节。

| 问题 | 实施前源码依据 | 对使用的影响 |
| --- | --- | --- |
| 默认编辑区仍兼任内置组目录 | `ui/workspace.rs::workspace_groups_panel` 按完整模块目录生成类别和行，未启用模块仍展示 | 用户看到的是可选功能清单，当前实际配置的组不够突出 |
| 成员编辑还有一层开关 | `ui.rs::policy_group_detail` 必须先点击编辑成员，再显示候选和搜索 | 展开组后仍不能直接加成员 |
| 地区筛选、批量加入藏在菜单 | 同一函数的操作菜单包含显示筛选、加入匹配成员、移除匹配成员 | 从折叠组按地区批量加入需约 8 次点击 |
| 成员搜索上下文不稳定 | `app.rs::edit_template_policy_group` 重置编辑开关，但成员搜索和来源、地区值是共享状态 | 换组后可能继承旧筛选，却没有清楚说明 |
| 规则库默认截断且没有完整浏览入口 | `ui/workspace/inline_rules.rs::workspace_inline_rule_picker` 在空搜索时 `truncate(8)` | 用户不知道还有哪些规则，必须猜搜索词 |
| 单条规则也要求选择后确认 | 同一选择器使用 rule_picks，最后统一添加 | 加一条规则也需要额外确认 |
| 候选规则添加前不能直接看正文 | 候选行只有选择；正文入口在已添加规则中 | 用户得先加入配置才能判断规则是否适合 |
| 正文编辑还要求二次进入 | `workspace_inline_rule_content` 默认只读，另有编辑内容、保存修改 | 查看并编辑一条规则至少经过查看、进入编辑两层 |
| 整体保存仍要求先保存正文 | `app.rs::prepare_yaml_output` 对未保存正文直接返回错误 | 最后点击保存时，还要找回局部保存按钮 |
| 顶部状态不能说明是否已保存 | `generator_page` 固定显示可保存或导入；菜单由 8 项扩展至 11 项 | 用户不清楚修改是否已进入我的配置，常用入口又变长 |
| 保存关联重启后丢失 | `generated_saved_config` 初始化为 None，未随草稿恢复 | 重启后不能可靠地继续更新上一份保存结果 |
| 模板显示与选择状态不准确 | `workspace_template_bar` 标签为模板·精简等，选项为精简等；共用选择器用标签等于选项判断选中 | 当前模板项不能正确勾选，自定义模板名称也未直接显示 |
| 错误时摘要容易误导 | `workspace_groups_panel` 对生成错误取 `.ok()`，成员摘要依赖生成结果；规则摘要只数规则集 | 无效规则可能让有成员的组显示 0 成员，手写规则不计入摘要 |
| 节点与 YAML 存在人为截断 | 节点列表 `take(160)`，YAML 预览 `take(400)` | 部分已有节点或配置内容不能直接浏览 |
| 搜索快捷键不跟随正在操作的区域 | 根部 Ctrl+F 分支没有成员编辑上下文，正文编辑也会指向只读搜索 | 键盘操作容易把焦点送到另一区域 |
| 两套编辑体验仍有差异 | 生成页与我的配置分别维护组、成员、规则表单；状态语义也不同 | 保存后继续编辑需要重新适应，不能作为已经统一的编辑器宣传 |

## 4. 生成页布局与默认呈现

现有区域位置保持不变。顶部左侧显示当前配置名称和保存状态，右侧保留保存、导入 Clash Verge；预览作为辅助按钮。配置名称可原位编辑，避免再打开一个命名表单。未命名配置可以自动生成合理名称并直接保存，改名是可选操作。

节点区直接提供添加、搜索和节点列表。批量操作只在选中节点或筛选生效时出现，不给每一行增加一套文字按钮。节点编辑、启用、排序、二维码保持可发现，不搬入三点菜单。

分流区显示当前配置实际启用的组，保留必要基础组。未启用的内置组从新建策略组的内置候选中选择，禁用组可按需查看；不在日常编辑列表里铺满全部服务类别。模板选择和 DNS 覆写留在分流区标题附近，不在这里展开基础设置。

组默认是紧凑行。点击后只展开当前组的成员、已添加规则和必要类型参数，不自动展开规则库或正文。展开组后，成员搜索和添加能力立即可用，不再有编辑成员开关。添加规则和点击某条规则才展开相应内容。

预览默认关闭，打开后使用当前配置内容。长配置和长列表允许完整浏览，不改变既有窄窗口下的预览位置。禁止通过缩小字体、固定小高度或层层卡片压缩内容。

## 5. P0：先让常用路径真正方便

### P0-1 成员选择和批量操作

- 展开组即可搜索、勾选成员；已选成员优先，节点与其他策略组清楚区分，名称可查看完整内容。
- 来源、地区筛选直接显示在成员区，只有实际存在多个来源或地区时才展示相应控件。
- 筛选后直接出现加入当前结果；存在可移除的已选结果时再出现移除当前结果，不藏入操作菜单。
- 全部节点的继承状态和手动添加的其他策略组明确区分，不用一个看似相同的勾选制造歧义。
- 切换组时，搜索与筛选按组记忆或重置并明确提示；不能把另一组的隐藏筛选直接套过来。
- 成员排序保留拖动，去掉每个成员都必须打开菜单才能移动的依赖。

验收：展开组后添加一个成员最多 2 次点击；按地区批量加入最多 4 次点击；搜索和批量操作不改变其他组。

### P0-2 添加规则和查看正文

- 规则库默认可浏览完整目录。常用推荐单独标明，不把推荐数量当成整个规则目录。
- 候选行显示名字、来源、归属和添加状态；点击名字可先查看正文，查看不修改当前配置。
- 单条规则直接添加到当前组；批量选择保留独立确认，只在有待添加选择时显示确认区域。
- 属于其他组的规则显示现有归属，移动时明确说明从哪个组移到哪个组；同组重复添加无副作用。
- 添加后的规则在当前组立即可见，不跳到全局规则页，不重置搜索位置。
- 已添加规则点击名字即可在当前组内查看并编辑正文；原始来源和本地覆写有清楚状态，编辑不会修改远端规则源。
- 查看失败显示当前来源和就地重试；有缓存时允许继续浏览缓存，不阻挡无关组编辑。

验收：从折叠组添加一条规则最多 3 次点击；查看并进入编辑最多 2 次点击；不输入搜索词也能看到全部规则；在加入规则前就能检查它的内容。

### P0-3 一次保存处理当前编辑

- 保存、导入共用一条提交过程：收集当前名称、组参数、成员和正文草稿，逐项校验，应用有效编辑，再生成并保存当前结果。
- 正文草稿检查覆盖当前配置中仍有有效归属的规则，包括已经收起编辑区的草稿；不能只检查屏幕上正在打开的一条。已删除、移出或禁用规则的未完成草稿单独保留，不误应用到当前输出。
- 有效正文草稿在整体保存时一并应用，不再要求先找局部保存修改。无效正文仍保留，自动展开并聚焦具体错误行，禁止输出旧结果冒充当前配置。
- 未命名时直接采用自动名称保存，不强制经历打开命名表单和再次确认。名称可随时原位编辑。
- 本次编辑更新同一份已保存配置；保存目标、草稿和基准版本可在重启后恢复。恢复时核对目标是否被修改，不能因恢复关联而覆盖后来手改的 YAML。
- 显示未保存修改、已保存到我的配置、保存失败等真实状态。草稿已保留和配置已保存分开表达，只有实际写入期间才显示正在保存。
- 已保存状态可直接打开对应配置，不再通过更多菜单寻找；修改名称也从名称处直接完成。

验收：首次和后续普通保存均为 1 次点击；Ctrl+S 与按钮行为一致；重启后正常保存仍更新同一记录；冲突时给出加载原配置或另存当前草稿的具体操作，避免只显示阻断文字。

### P0-4 操作反馈与错误定位

- 名称、参数、正文错误显示在对应对象旁，并提供焦点定位；不能只依赖 3 秒 toast 或远端错误条。
- 摘要从当前组与规则数据统计，不依赖整份配置生成成功。手写规则和规则集分别统计，不能把有效成员显示为 0。
- 添加、移除、排序后立即反映结果，保持当前组展开和滚动位置。
- 删除使用直接图标，适用操作提供短暂撤销；不恢复删除展开表单或复制策略组功能。
- 模板显示实际名称和正确选中状态。应用模板时保留节点，清楚说明替换的是分流；已有自定义分流可撤销恢复。

## 6. P1：减少输入、菜单和等待

### P1-1 添加节点入口统一

一个输入区自动识别订阅 URL、单个节点和多行节点链接。名称可选；粘贴后明确显示识别结果、有效数量和错误行，提交后自动定位新加入节点。保留从 YAML 提取节点入口，并明确其用途；完整配置导入继续保持独立，不偷偷覆盖规则。

普通添加不要求先选择订阅或单节点模式。多行内容失败时保留原文，允许修正后再提交；重复节点说明哪些已存在，不用笼统的添加失败。

### P1-2 更多菜单与对象操作

顶部更多菜单目标为最多 3 项低频完成操作，例如复制 YAML、另存为新配置、复制实时订阅地址。名称修改、查看保存结果回到名称和状态旁；规则排序在规则区域操作；模板保存和管理归到模板入口；节点区保持可见。

诊断、变更记录等归到已有相关区域，不新增管理页。链式代理、筛选组等保留当前页的按需入口，明确名称和用途，不默认展开整套表单。低频入口收敛不能造成原功能消失。

### P1-3 键盘、列表与性能

- Ctrl+F 聚焦当前操作区：成员搜索、规则库搜索、正文查找或节点搜索。正文编辑时不把焦点送到隐藏的只读搜索框。
- Ctrl+S 保存当前配置；Enter 提交当前短输入；Esc 只退出最上层编辑或关闭当前辅助区，不撤销整个组，也不丢失正文草稿。
- 节点列表完整可达，改用虚拟列表等方式消除 160 节点截断；YAML 预览可完整浏览，采用适当渲染方式消除 400 行限制。
- 使用配置变更版本缓存生成结果，搜索输入、悬停或其他无关重绘不重复生成整份 YAML。批量操作统一提交一次更新，避免逐项通知和重复持久化。
- 实施前后都用同一份 100 节点数据测操作响应；目标为常用点击反馈不超过 100ms、搜索结果更新不超过 150ms。记录实际值，不以编译或单测通过替代流畅性结论。

### P1-4 Clash Verge 导入过程

保存、发布、发送客户端的过程有明确状态，进行中防止重复点击。失败就地重试，已经保存的结果保留，重试不新建另一份配置。

只把实际发送成功标为已发送到 Clash Verge。已有订阅拉取记录可作为已被客户端读取的依据；没有可靠证据不显示已导入或已启用。客户端未安装、链接关联未启用和本地服务不可用分别给出具体处理路径；保持本地订阅工作的说明放在相关状态旁，不要求用户先理解服务设置。

不直接写 Clash Verge 的配置目录，不擅自切换它正在使用的配置。

## 7. P2：让继续编辑保持一致

统一生成页和我的配置中名称、组类型、成员、规则查看编辑和错误提示的交互。先共享组件和操作语义，再评估是否让完整 YAML 与可视化配置进入同一套编辑界面。

实施前必须验证未知 YAML 字段、注释可保留范围、禁用节点与组的元数据、规则正文覆写、来源刷新、草稿及历史记录。不能把完整手写 YAML 转成生成模板后覆盖原文件。无法完整保留的部分先使用原有 YAML 编辑能力，不宣称已统一支持。

此项不阻挡 P0 和 P1；暂不做数据库模型合并或迁移，也不把已有配置页重画一遍。

## 8. 操作次数验收表

以下从折叠组或普通编辑页开始，计按钮点击和菜单项选择，不计文字输入、拖动和系统客户端自身确认。整改后的次数由源码事件路径推导，尚未通过桌面操作测量。

| 日常任务 | 实施前路径或限制 | 已实施的源码路径 |
| --- | --- | --- |
| 添加一个组成员 | 展开组 → 编辑成员 → 点击成员，约 3 次 | 展开组 → 点击成员，2 次 |
| 按地区批量加入 | 展开组 → 编辑成员 → 操作 → 显示筛选 → 地区 → 选地区 → 操作 → 加入匹配，约 8 次 | 展开组 → 地区 → 选地区 → 加入结果，4 次 |
| 添加一条分流规则 | 展开组 → 添加规则 → 选择 → 确认，约 4 次 | 展开组 → 添加规则 → 单条添加，3 次 |
| 查看并编辑规则正文 | 展开组 → 查看/编辑 → 编辑内容，约 3 次 | 展开组 → 点击已添加规则名称，2 次 |
| 浏览全部规则 | 空搜索只显示 8 项，没有直接完整目录 | 无需猜关键词，完整目录可达 |
| 首次普通保存 | 点击保存 → 命名表单 → 确认，至少 2 次 | 自动名称可用，1 次保存 |
| 正文修改后保存配置 | 必须先保存正文，再保存配置 | 1 次整体保存，自动应用有效草稿 |
| 重启后继续保存 | 保存关联不恢复，可能新建副本 | 恢复目标并核对版本，正常情况下 1 次更新同一份配置 |
| 查看已保存配置 | 更多 → 查看已保存配置，2 次 | 点击保存状态，1 次 |
| 添加订阅或节点 | 打开添加后可能还要选择模式 | 单个输入自动识别，最多添加和提交 2 次 |

## 9. 实施顺序与检查方式

1. **第一批：P0。** 先完成成员、规则单条添加与预览、整体保存和可靠状态。核心流程稳定后再调整菜单。重点文件：`ui.rs`、`ui/workspace.rs`、`ui/workspace/inline_rules.rs`、`app.rs`、`app/workspace.rs`、`app/workspace/rules.rs`、`app/saved_configs.rs`、`app/lifecycle.rs`。
2. **第二批：P1。** 自动识别输入、键盘行为、完整列表、减少无关生成与导入重试。重点补充 `app/generation.rs`、`desktop.rs` 和必要的原有发布接口。
3. **第三批：P2。** 按字段保留要求评估共享编辑，不在便利性整改中顺带做数据迁移。涉及 `ui/saved_configs.rs`、`app/saved_editor.rs`、`saved_document.rs`。

每批先按以上日常任务检查完整事件调用路径，再做格式化、严格 Clippy 和适当回归。新增测试只覆盖有实际风险的行为：保存目标恢复、正文草稿统一提交、批量操作不影响其他组、删除撤销、完整 YAML 数据保留及导入重试不重复存档。节点规模以 100 为准，不扩张为大规模压力测试。

响应耗时通过必要的代码计时和 100 节点基准记录，区分输入反馈、生成耗时及网络等待，不为测量而自动操作用户窗口。

遵守用户要求：不截图、不进行未请求的桌面自动操作、不改真实数据库、不关闭用户程序、不提交或推送。编译检查与功能回归不代表视觉和交互实测；验收记录必须说明检查方法，不能把推导的点击次数写成实测结果。

只维护一个可用程序入口 `target/release/swiftsub.exe`。每批完成后更新该入口；运行中无法覆盖时使用临时构建文件，交付前处理旧副本，不能继续留下多个供用户选择的 EXE。

## 10. 本计划的完成标准

用户可以在现有页面位置内，快速找到当前组、直接选成员、先看规则再加入、直接修改正文，然后一次保存或导入；重启后还能继续编辑同一份配置。默认展示的是当前配置，完整目录和高级能力在需要时可达，错误可就地修复。以上操作次数、保存状态和数据保留条件均满足后，才算本轮体验优化完成。

## 11. 本轮实施与验证记录

### 已落地的便利性改动

- 默认列表显示当前启用组和必要基础组；未启用内置组从「新建」加入，分类默认展开。模板名称与选中状态正确反映当前模板。
- 打开策略组即可搜索、勾选成员；多来源、多地区时直接提供筛选，已选成员优先，筛选结果可一次加入或移除。自动纳入的节点标注「自动」，与手选成员区分；切换组重置筛选。
- 规则库不再截断为 8 项；单条直接添加，批量选择才需要确认。候选名称可先看正文，已添加名称直接打开可编辑正文；来源、归属、本地覆写和草稿状态在对应规则旁显示。
- DIRECT / REJECT / REJECT-DROP 等没有策略组卡片的目标，在有规则或正在编辑时提供同页规则入口；筛选组和链式组的规则编辑显示在现有工具区域。无效正文展开具体归属并聚焦编辑区，自定义组所属分类也会展开。
- 整体保存收集全部有效归属、匹配来源的正文草稿，包括已收起编辑器的草稿；先校验，再提交。删除、停用或旧来源草稿继续保留，不误用于当前输出。撤回或恢复来源遇到损坏的草稿存储会报告错误并保留原数据。
- 首次保存直接使用自动名称；可在顶部原位改名。重复保存和导入更新同一记录，重启恢复历史保存基准；数据库手改、已有编辑器草稿和外部文件修改均有覆盖保护。冲突旁可直接查看保存结果或另存。
- 删除组、移除规则集和替换模板提供撤销；有后续分流修改时拒绝覆盖。切换模板、关闭正文和撤销均先保存正文草稿。
- 添加区统一识别订阅 URL、单个节点、多行链接、Base64 与 YAML 节点内容；剪贴板内容先填入输入框供检查。无效行保留原文，重复订阅复用已有来源，新增节点自动定位。完整 YAML 导入继续独立，避免意外替换分流。
- 顶部「更多」保留复制 YAML、另存为新配置、复制订阅地址；模板操作位于模板入口，规则顺序和筛选链路等位于分流工具入口。
- Ctrl+S 保存当前配置，Ctrl+F 跟随成员、规则库或正文上下文；正文与 YAML 编辑器使用原生查找。Esc 先退出查找，再收起编辑区并保留草稿；Ctrl+Enter 提交多行添加。
- 节点和 YAML 预览使用虚拟列表，取消 160 节点 / 400 行截断。生成缓存依据实际节点与生成选项失效，搜索与无关重绘复用结果；批量成员操作仅提交一次更新。有效正文草稿参与实时预览，错误时保留最后有效预览并说明原因。
- 导入先保存并发布当前版本，再发送客户端链接；客户端调用在后台执行，显示发送进度并禁止重复发送。失败保留记录并支持原入口重试；成功只显示「已发送」，不把发送链接等同于客户端已启用配置。

## 12. P2 字段保留评估与后续边界

已检查 `saved_document.rs` 的实际 YAML 编辑与生成模板之间的差异。当前应继续保留完整 YAML 编辑能力，不能直接将手写配置转换为生成模板后覆盖。

| 数据 | 当前边界 | 合并编辑器前的要求 |
| --- | --- | --- |
| 未知顶层 / 节点 / DNS 字段 | 现有 YAML 可视化编辑基于原值修改，有保留未知字段的回归；模板生成不是完整 YAML 的无损转换 | 使用原文档作为基底，仅修改用户操作对应的字段 |
| 注释与格式 | YAML 解析后重新序列化不能承诺保留注释；原始 YAML 文本保存不主动格式化 | 选择可保留注释的修改方式，或者明确修改范围并保留可恢复原文 |
| 禁用节点、组和成员 | 现有文档编辑有独立元数据及恢复测试；生成模板的停用逻辑不同 | 先统一恢复语义与元数据映射，禁止静默遗漏 |
| 正文覆写与来源 | 生成工作区覆写与匹配来源草稿独立存储 | 新界面同时保留来源身份、正文覆写与未完成草稿 |
| 刷新、历史、冲突 | 我的配置已有来源同步、历史与冲突处理；生成工作区使用历史保存关联 | 共用同一份文档提交和历史记录，保留手改冲突保护 |
