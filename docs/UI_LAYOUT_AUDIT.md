# 布局结构审核与整改

日期：2026-11-25。按用户要求仅检查源码、布局约束和回归结果，不进行截图或桌面自动操作。本次不重新分配节点、策略组、规则的操作位置。

下文记录本轮布局整改时的结构。后续 [YAML 流程简化](YAML_WORKFLOW_SIMPLIFICATION.md) 已将主导航收敛为「配置编辑 / 我的配置 / 设置」，复制与导出直接显示在编辑页顶部，高级 JSON 默认收起；节点、策略组和规则的常用编辑位置继续保留。

## 核心问题

原设置页已经有「生成工作区 / 本地订阅 / 规则与生成 / 桌面与编辑 / 数据与关于」分类，却在「规则与生成」内用下拉菜单切换「基础与 DNS / 测速 / 单组测速 / 高级配置」。分类是固定的少量导航项，不是需要从大量数据中选择的值。把它们隐藏进下拉框增加查找步骤，也让用户无法看见有哪些设置。

该页同时把内部表单限制在 620 逻辑像素宽，并额外包裹「生成设置」卡片；规则来源又独立放在该卡片的底部。结果是分区、标题和宽度约束互相叠加，内容出现拥挤与留白并存的问题。

| 组内添加规则 | 三个固定添加方式又使用下拉菜单 | 规则库、自定义链接、手写规则直接显示为短选项，选项和收起按钮允许换行；来源筛选仍使用数据下拉 |

| 模板 | 内置模板信息短，自定义模板使用可换行行布局和列表滚动 | 保留直接选择、编辑和管理能力 |

| 保存行为 | 高级配置保存会重新加载所有基础与测速输入 | 保存高级配置时只校验并提交当前配置，不重载同页其他设置输入 |

## 本轮布局规则

- 固定的页面导航和少量模式选项直接可见；下拉用于模板、组、来源、镜像、类型等实际数据选择，以及次级操作菜单。
- 总设置使用左侧一级分类与右侧清楚分区，不在一个分类中继续隐藏另一套分类导航。
- 默认值留在总设置；当前组的成员、类型、名称、规则添加及正文编辑留在当前组旁。
- 表单利用可用宽度，短数值输入控制长度，长地址输入可伸缩；标题和操作行允许换行。
- 页面内容使用一个主滚动容器；已有节点、规则正文和长结果列表保留必要的独立滚动。
- 错误显示完整文本与实际位置，不用截断文字或统一的远端错误区让用户猜测。
