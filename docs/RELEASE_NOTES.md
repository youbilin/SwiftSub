# SwiftSub v0.1.0 验收与发布说明

验收日期：2026-11-15。平台：Windows x64。此文件记录本地产物，不表示已创建 GitHub Release。

## 本次更新

- 规则库完整展示未启用组的规则，选择时启用对应组；来源栏提供独立开关，可叠加内置、MetaCubeX 扩展、blackmatrix7、Loyalsoldier、ACL4SSR，并继续逐条选规则和目标。当前目录共 129 条。
- 新增 23 个服务策略组，完整预设共 46 组。精简版仍包含国内直连、非中国域名分流及最后的漏网之鱼；三个必需组可从生成页直接编辑，地区组继续排除。
- 具体产品排在厂商合集前，服务规则排在范围规则前；国内 IP 放在非中国域名之后，最后为 MATCH。移除上游已不存在的 Steam IP 文件引用。
- 保存新配置前可填写名称，也可直接保存并导入 Clash Verge。我的配置支持改名、编辑 YAML、保存修改、另存一份、完整 YAML 文件导入、复制、导出和删除。
- Clash Verge 导入携带保存的配置名和独立订阅地址，中文及特殊字符正确编码，名称位于 URL 参数前；Windows 优先使用专用协议，兼容旧 Clash 协议。已有修改会先校验保存再交给客户端。
- 原节点导入按钮改为「粘贴节点 / 从 YAML 提取节点」。设置中的旧生成配置管理改为「生成工作区」，默认打开本地订阅设置。
- 日夜按钮使用线条 SVG；精简分流编辑、来源说明及文件路径提示，保留必要状态和错误。

## 数据与文件

默认数据目录 `%APPDATA%\SwiftSub`。每条保存记录的正文写入 `configs/<独立ID>.yaml`，名称、正文和原生成设置存入 SQLite；同名记录也使用独立文件。生成器和订阅源刷新不会改写已有保存文件。「保存修改」更新当前记录，「另存一份」创建新记录。

数据库 schema v3 保持兼容。未完成的 YAML 编辑单独持久化，格式检查或写入失败时保留原文件。历史版本已经覆盖掉的正文无法恢复。客户端通过本机 HTTP 服务获取保存记录，使用本地订阅时需保持 SwiftSub 运行。

## 使用与产物

1. 解压运行 `swiftsub.exe`，生成页选择预设并按来源勾选规则。旧的自定义选择继续保留；需要新增完整预设的组时，重新点击「完整」。
2. 点击「保存新配置」，输入名字，选择「保存到我的配置」或「保存并导入 Clash Verge」。
3. 在「我的配置」直接改名字和 YAML，然后保存修改、另存或导入客户端；完整 YAML 文件也从这里导入。

本次使用独立产物目录，避免覆盖正在运行的旧程序：`target/release/routing-final/swiftsub.exe`。

发布包 `target/release/SwiftSub-v0.1.0-routing-update-windows-x64.zip`。可执行文件 36,071,424 字节，SHA-256：

```text

```

发布包包含程序和说明，不含数据库、订阅凭据或测试密钥。更新后重新打开新程序即可使用，本轮没有中断用户正在运行的旧实例。

## 源码核对

参考 SubBoost 提交 `92608545991003756a58f217261c52507c76a8b4` 的分组目录与模板保存流程，采用独立 Rust / GPUI 实现。Clash Verge Rev 提交 `b2689b4220fd4cb8255b1f55331254a469870aff` 的 `src-tauri/src/utils/resolve/scheme.rs` 支持两个协议、提取名称并将 `url=` 后的内容作为地址，因此名称必须放在地址参数前。
